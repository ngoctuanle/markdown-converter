## Decisions made during the work

- **Task 1:** The folder had no git history, so the existing spec and plan were committed first (`a1636d8`) as the starting point.
- **Task 3:** The reservation type also derives `Debug`, which the plan didn't list, so later code can unwrap results that hold one. It only adds a capability.
- **Task 4:** Two extra tests and fixes beyond the plan. (1) A name made by deduplication is never handed out again, so alt texts "Logo", "Logo", "Logo 2" give `logo`, `logo-2`, `logo-2-2` instead of two `logo-2` files overwriting each other. (2) Alt text that slugs to a Windows device name (`con`, `nul`, `aux`, `prn`, `com1`–`9`, `lpt1`–`9`) falls back to `image-NNN`, because Windows can't create those files.
- **Task 5:** Small additions to the plan. A time-out shorter than a minute shows seconds instead of "0 min". If pandoc is killed by a signal with no error text, the row says so. When pandoc times out, the app stops waiting at once instead of waiting for the output pipes to close.
- **Task 6:** The plan didn't say what the `image-NNN` number counts. It counts each new picture copied, in document order: a picture used twice keeps its first name, and web links don't use up a number, so numbered names have no gaps. Picture links written with `%20`-style escapes are also found.
- **Task 8:** If a conversion crashes inside the app (a bug, not a pandoc error), its row is marked Failed with "Internal error while converting" and the worker keeps going.
- **Task 10:** The window has a minimum size of 800×500 so both the file list and the preview stay usable. API notes: the "Add files" dialog result is handled with `cx.spawn_in` rather than `cx.spawn`, because adding files can show a notification, which needs the window. The "pandoc not found" notification is pushed with `window.defer`, because the window's notification layer doesn't exist yet while the view is being built. Dialog errors and settings-save errors show as error notifications.
- **Task 11:** The plan's `set_readonly(true, cx)` on the editor state doesn't work in gpui-component 0.9.1: the editor element copies its own read-only flag (default off) into the state every time it draws. The Markdown view is made read-only with `Editor::readonly(true)` on the element instead, which still allows selecting and copying. The Done-row summary now says "1 image" and "1 warning" for one, and "{n} images" and "{k} warnings" otherwise. The preview doesn't read the file again when the same converted file is shown again (the window re-sends the selection on every conversion update).
- **Task 12:** `before-packaging-command = "cargo build --release"` builds for the host only, but packager looks in `target/<triple>/release`, so `scripts/package.sh` also runs `cargo build --release --target <triple>` first. `locate()` needed no change: packager puts resources in `Contents/Resources`. The universal path (not run) packages the `.app` from the arm64 build, `lipo`s the two binaries into it, ad-hoc signs, and makes the `.dmg` with `hdiutil`.
- **Windows packaging (2026-11-11):** `scripts/fetch-pandoc.ps1` and `scripts/package.ps1` replace Git Bash on Windows and make the NSIS installer, a portable zip and (with `-Formats …,wix`) an MSI. Both package scripts set `CARGO_BUILD_TARGET`, so packager's `before-packaging-command` builds into `target/<triple>/release` and finds it up to date; the release build no longer runs twice. `.cargo/config.toml` adds `+crt-static` for MSVC, so the exe imports only system DLLs (checked with `dumpbin /dependents`) and needs no VC++ Redistributable. The WiX packager ignores a resource's target file name, so the MSI installed the licence as `COPYING.md`. The scripts now stage it as `vendor/pandoc/current/pandoc-COPYING.md` and Cargo.toml's `pandoc*` glob picks it up under that name for every format. The NSIS uninstaller offers to delete `%APPDATA%\markdown-converter`. Verified on Windows 11: `cargo test` (72 + 15) passes. The NSIS installer installs per user without admin; the installed app, started with `PATH=C:\Windows\System32`, finds its bundled pandoc. The 15 conversion tests pass against the installed `pandoc.exe`. The silent uninstall removes files, shortcuts and the registry entry. The MSI's file layout was checked with an admin extract, not by installing it.

- **Final review:** Markdown is now written with `-t gfm` (raw HTML allowed) instead of `gfm-raw_html`, so tables too complex for pipe syntax survive as HTML `<table>`s instead of `[TABLE]`. Before writing, `src/ast.rs` normalises the AST so complex tables are the only HTML left: raw HTML dropped, Image/Link attributes cleared, Figures unwrapped with the caption as a paragraph. It also goes beyond the review's ruling, because `gfm` would otherwise emit `<span>`, `<div>`, `<u>`, `<sup>`/`<sub>` (seen in the EPUB and ODT fixtures): Span/Div are unwrapped, Underline becomes emphasis, SmallCaps upper-case, and Superscript/Subscript Unicode or `^(…)`/`_(…)`, as `gfm-raw_html` did. Output for every other fixture is unchanged. Linked local pictures are copied only if they have a picture extension and aren't on a network share (`\\host`, `//host`, `file://host`), otherwise they're left as links with "Picture not copied: …". `file:` URLs count as local paths. `data:image/…;base64` pictures are saved to the assets folder (each payload once; unknown types and bad base64 are kept with a warning). `%`, `#` and `?` are percent-encoded in picture links. Closing the last window quits the app, and there's a Quit menu item (cmd-q, ctrl-q elsewhere). Windows release builds have no console. A `Reservation` deletes its output when dropped without `commit()`, so errors and panics leave nothing behind. On quit the app drops queued jobs, kills running pandoc processes (a stop switch shared by `Pandoc` clones, polled every 50 ms) and waits up to 2 s for jobs to delete their partial output. The preview reads files in the background, ignores results for a file no longer selected, loads at most 2 MB (cut at a line break, with a note), and lists the file's conversion warnings above it. Dropped folders skip `~$…` lock files and `.`-files.
